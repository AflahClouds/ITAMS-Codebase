## Clouds v1 task policy

## Clouds living-spec addition

- For every corrected high-risk deterministic defect, retain a permanent deterministic regression test unless an explicitly accepted behavior change supersedes it. Run targeted and relevant broader checks.
- Task work must leave the temporary feature intact through clean workflow/equivalent evidence; guide-owned post-workflow consolidation removes temporary artifacts only afterward.
- Order one bounded builder, frozen candidate, fresh read-only reviewer, same bounded-builder repair, and same bounded-reviewer re-review. No concurrent writer/reviewer work. Add fail-before coverage for any demonstrated checklist/HEAD/assignment drift defect.
- End the task ledger with implementation and verification complete, a pre-closeout stale-material/self-description review of the active tree, and zero unchecked tasks. The task ledger excludes guide-owned post-convergence canonical consolidation and checklist review, temporary-artifact deletion, routing restoration, and post-cleanup checks. This repository's deterministic candidate/source parity is a separate maintainer release check, never a task imposed on an installed project. Candidate upload/install/push/release remain excluded.

- If the feature includes consequential deterministic financial or operational data processing, tests are mandatory. Place concrete test tasks before production implementation tasks and require the intended failing result to be observed first. Cover relevant rounding, period, duplicate, missing-value, reversal, allocation-total, reconciliation, and idempotency boundaries.
- Trace each deterministic example and expected result from the specification to a named test task. Require the test to fail for the intended reason before the production change and pass afterward; do not replace executable evidence with a model assertion.
- Translate the plan's predecessor inventory into explicit cleanup tasks after successor proof. Include affected obsolete code, tests, dependencies, configuration, flags, documentation, and duplicate paths. Do not use a vague final "cleanup" item when exact targets are known.
- Keep temporary artifacts until task-tracked delivery, review, convergence, verification, and the temporary-artifact checkpoint are clean; leave deletion and canonical routing restoration to guide-owned closeout.
- Organize stable local Git checkpoints after each completed user story or coherent task group whose relevant checks pass. Checkpoints are logical, not time-based; stage only current-work files on the selected development branch. Defer any development push to the guide and constitution's separate affirmative authorization. Do not schedule an automatic merge to `main`; promotion requires explicit user approval and is separate from implementation convergence.
- Add one final pre-closeout repository-wide task that combines the reference/dependency and stale-material scan with verification that a fresh person or agent can understand, modify, test, operate when applicable, and resume the active tree from checked-in sources. Convergence cannot be complete while this pre-closeout review, implementation cleanup, context repair, checkpoint commits, or verification is pending; do not add post-convergence guide-owned work as unchecked tasks.
